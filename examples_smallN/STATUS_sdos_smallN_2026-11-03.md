# Status: small-N study of exact-moment substitution and impartial vectors (directive DIRECTIVE_sdos_smallN_moments.md)

Nothing in the package defaults or in the paper was changed. All scripts and JSON: `~/sdos_pkg/examples_smallN/` (zip in claudestuff).
Reference for every test: dense `eigh`. Random-vector moments are computed in the eigenbasis, `mu_n = N^-1 sum_i c_i^2 T_n(x_i)`, `c = V^T xi`; this is the same number as the Chebyshev recursion (checked: 4e-15) and the exact moments agree with `exact_chebyshev_moments` to 2e-15. Bounds: exact extremes widened by 1% (the package's `margin`). Half filling, spin 1.

3. **Maxent scans reduced** after my first attempt took hours (non-converging Newton solves run to 500 steps): M = 100 only, sizes N = 64, 512 (chain, SSH), 256, 864 (Kwon), 512 (Anderson), 20 seeds (5 for the known-failing R=1 cases), R = 1 and 16 only, no run with sigma floor 0 (plain R=16 floor 0 was run in the first attempt: same as with floor). E4 Maxent only for M <= N, 3 seeds, one system pair (Kwon 256, SSH 1024). KPM scans are complete (>=500 seeds N<=1024, 200 above). N=16384 anchor not rerun.
4. E4: Maxent E_BS error in the first run was stored as a total (unit bug); corrected in the JSON and script.
5. Error definition: E2 errors are against the **same pipeline fed the exact moment list** (same M, kernel, grid), so truncation is excluded; the cumulative error is given both ways (`cum_pipe`, `cum_true` vs the exact step function).

## Step 0 (code reading)
1. **Vectors / exact moments.** `exact_moments=K` never uses vectors: `dos.py:216-229` calls `exact_chebyshev_moments(Ht.M, K)` (`exact.py`: deterministic closed-walk sums over unit vectors, O(N)) and overwrites `mus[:, :K+1]` of every sample (`mus[:, :K+1] = mu_ex[None, :]`). Table I rows (`examples/dtw4096/dtw_electrons.py:48-51`): "impartial (3)" = `vectors="impartial", exact_moments=0` (`moments.py: impartial_vector`, Drabold-Sankey penalty, exact mu_0..mu_2 per vector, tr1/tr2 from `ScaledOperator.traces()`); "Rad. + exact K" = `vectors="rademacher", exact_moments=K`. The two can be combined (`vectors="impartial", exact_moments=K` is accepted); not with probing, and both are refused for generalized non-diagonal B (`dos.py:248-253`).
2. **sigma.** Substitution happens before `maxent_fit` (`dos.py:216-229`, then `:104-119`). In `maxent.py:138-144`: sigma_n = noise * std over the R samples / sqrt(R) **after** substitution, so for n <= K it is exactly 0, then raised to `sigma_floor = 1e-4`; for n > K it is the sampled standard error (unaffected by the substitution) floored at 1e-4; sigma_0 = 0. For R = 1 sigma = 0 everywhere, i.e. 1e-4 for all n >= 1. Sigma is used as independent (diagonal); correlations (H2) are ignored.
3. **Scaled operator.** Head moments are computed from `Ht = ScaledOperator(H, a, b)` built in the same call after the bounds (`dos.py:184-223`), so they are recomputed whenever the bounds change; nothing is cached. (Note: `sdos.dos` in `api.py:51-52,72` defaults to K = 4 for explicit sparse + diagonal B, `estimate_dos` defaults to 0.)
4. **Size guard.** None. Only warnings: `|mu_m| > 1` (bounds too tight, `dos.py:72`) and the ill-defined Fermi level. No check of M against N, no check of moment-list consistency.

## E1: moment-cone consistency (Toeplitz test) -- H1 is confirmed, and much earlier than predicted
Figure `fig_e1_cone.pdf/png`; data `results/e1_*.json` (40 seeds; 16-vector averages; impartial 20 / 6 seeds; M = min(4N, 400)).
* (a) exact lists: lambda_min(T_m) >= -6e-14 for all systems and m (the sanity check passes).
* (b) plain Rademacher, R = 1 and 16, and (d) impartial(3), R = 1 and 16: **never** violate (0 of every seed, every N, every system), as predicted.
* (c)/(e) **spliced lists violate almost always** (K = 2, 4, 8, 16; 80-100% of seeds for N <= 4096, 100% for SSH and Kwon at every N), also with the R = 16 tail and with impartial + splice. The first violating order is **m* ~ 12-40 independent of N** (chain: m* = 17-37 for N = 32 ... 4096; Kwon 18-40; Anderson 12-25), i.e. m*/N falls from ~0.5 to 0.007. It is **not** a "near N ... 2N" effect: the empty arcs of the spectral measure (band-edge margin, gaps) make lambda_min of T_m decay fast (see figure), and the 1/sqrt(N) noise of the sampled tail is larger than it once m is ~ 20-30. Larger K gives a later m* (K = 16: 25-37), the R-averaged tail gives a later m* by ~30%; the violation is deep (lambda_min -0.02 ... -0.7 at M = 400).
* Conclusion: the spliced list is almost never a moment list of a positive measure, at any N. This does not matter for KPM (linear) but is relevant to Maxent (E2/E4).

## E2: bias and variance
Files `results/e2kpm_*.json` (KPM, all), `results/e2maxent_*.json` (Maxent, reduced), `results/e2_zscore.json`, `results/e2_bias_origin.json`; figure `fig_e2_rmse.pdf/png`; table script `summarize_e2_kpm.py`, `summarize_maxent.py`.
**KPM E_BS (M = 100, R = 4, per orbital)**: RMSE relative to plain Rademacher at equal R: splice K=4: 0.04-0.10; K=16: 0.004-0.014; impartial(3): 0.08-0.15; impartial+K4: 0.04-0.10; at every N from 32 to 4096 (see JSON for R = 1, 2, 16 and M = 50, 200, 2N, 4N). Cost is the same for plain and spliced (the head is O(N)); impartial costs extra CG steps.
**Bias**: statistically nonzero (|bias| > 2 SE) in many cases, for *every* estimator including plain vectors, but small compared with the plain RMSE (largest relative bias: SSH, spliced, bias ~ 1.5 sd of the spliced estimator = 2e-3 per orbital, which is 3-5x smaller than the plain-vector RMSE). Origin (`e2_bias_origin.py`): with the Fermi level held at its exact value, E_BS is a *linear* functional of the moments and is **unbiased within 2 SE for plain, K = 4 and K = 16 splices** (b/se between -1.5 and +1.7, 2000 seeds). The bias is the nonlinear canonical step (E_F from the noisy IDOS), which is largest in gapped systems and is already present in plain vectors. So H3 holds for KPM: substitution does not bias a linear reconstruction; the E_BS bias is due to E_F, not to the splice.
**Practical threshold (as defined: |bias| < 2 SE and RMSE < plain)**: the RMSE condition holds from N = 32 up. The bias condition (with >=500 seeds) is **not met by any estimator in SSH, and in part of the Kwon cases, even plain**; it is met by the splices in the chain for N >= 128 (K=4), 64 (K=16) and in Anderson at all N tested. I therefore also propose the practical criterion bias < 0.1 sd of plain: it holds for all spliced/impartial estimators at all N tested (the spliced bias is 1/3-1/2 of the plain bias in absolute terms, the plain bias being itself 0.1-0.4 sd_plain... see JSON). No small-N threshold below N = 32 was found for KPM.
**Maxent (M = 100; per-orbital RMSE; reduced scan)**
* R = 16, sampled sigma + floor (the package behaviour with R >= 2): splice K=4 RMSE 6-40x below plain (e.g. Kwon 256: 3.7e-3 vs 7.1e-2; chain 512: 5.7e-4 vs 1.0e-2); K=16 even lower; converged in 90-100% of runs (K = 16: 90%, median 20-66 Newton steps against 11-17 for plain). Impartial(3): between plain and K=4. True cumulative error equal for all (it is dominated by M = 100 broadening). Bias/SE up to +7 in SSH (all estimators; magnitude << RMSE_plain).
* **R = 1 (sigma = floor only): the splice breaks Maxent.** K = 4, 16 and impartial+K4 with one vector: **0-20% converged (500 steps), E_BS errors 0.1-4 eV per orbital (larger than plain), cumulative error 2-4000 (garbage)** at every size tested (chain 64/512, SSH 64/512, Kwon 256/864, Anderson 512). Plain and impartial(3) R=1 converge (90-100%). This is H1 in practice: an inconsistent list with only sigma = 1e-4 has no Maxent solution.
* Floor 0 for plain R=16: no difference. (Spliced floor 0: not rerun; the first attempt reached 83% convergence at 6 seeds.)
**z-score of impartial(3)** (`results/e2_zscore.json`, 2000 vectors N<=1024, 600 above, rms over n = 3..63): chain N=32: 1.64, 64: 1.27, 128: 1.13, 256: 1.14, then 1.05, 1.02, 1.04, 0.93; Rademacher control 0.8-1.2. So impartial(3) is **biased at the 1-sigma level only for N <~ 100** (z = 1.6 at N = 32) and unbiased at the sampling resolution for N >= 512 (other systems in the JSON/log).

## E3: covariance and control variate (`results/e3.json`; 20000 / 8000 vectors)
1. Covariance of plain Rademacher moments: the **Gaussian formula N^-1(mu_{m+n} + mu_|m-n|) fails** by 3% (chain), 13% (SSH), 25% (Kwon), 80-85% (Anderson) of the largest entry; the **exact Rademacher formula** (Gaussian minus 2 N^-2 sum_i (T_m)_ii (T_n)_ii, local Chebyshev diagonals from the eigenvectors) agrees to 2-4%, which is the statistical noise. So H2's correlation formula is right for Gaussian vectors, but for Rademacher the diagonal term matters (strongly in disordered or non-translation-invariant systems).
2. Control-variate tail (beta from 400 independent pilot vectors, M = 100, 500 seeds, KPM E_BS): variance ratio cv/splice 0.65-1.0 for K = 4 and 8 in the chain, Kwon, Anderson; cumulative error ratio 0.9-0.95. Large gain only in gapped systems at K = 16: SSH 0.01 (var), Kwon 256 0.19 (var, cum 0.43). The cv estimator keeps the E_F bias. **Verdict**: not worth adding as default; gain below 15% in std for K <= 8 in ordinary systems. (Maxent with cv not tested.)

## E4: resolution regime (Kwon 256, SSH 1024; M = N/4 ... 4N; `results/e4_*.json`, KPM complete, Maxent M <= N)
* KPM plain / spliced / exact: no failure at M ~ N and beyond (M = 4N): KPM remains stable; the cumulative error decreases slowly with M (kernel width) and the E_BS error of the splice stays ~5e-3 (Kwon) / 1e-3 (SSH) per orbital, plain 3e-2 / 8e-3 (R = 4), constant in M (it is the stochastic error, not resolution). The spliced list violates the cone at m* = 21 (Kwon) / 18 (SSH) in all seeds for every M; plain never.
* Maxent M <= N: plain, splice (R=4, sampled sigma) converge (SSH M = N/2: 67% for the splice); splice E_BS error 6e-4 .. 1e-3 vs plain 3e-2 (Kwon) and 7e-4 vs 8e-3 (SSH). **Maxent with the exact moment list** (floor 1e-4) takes 42-129 Newton steps and at M = N (Kwon 256) **does not converge** (499 steps); M > N for Maxent was not run (memory/time). The package does **not warn** when M reaches N.

## What is fine and where it fails (plain statement)
* **KPM with the splice**: fine at all N tested (32 to 4000, four systems), M from 50 to 4N; RMSE of E_BS and the cumulative curve are 10-200x below plain vectors at the same cost; the moment list is not a positive-measure list, but KPM does not care. The residual E_BS bias is the Fermi-level step, shared with plain vectors.
* **Maxent with the splice and R >= 4-16 (sampled sigma)**: fine from N = 64 to 864 (tested), converging 90-100%, RMSE 6-40x below plain.
* **Maxent with the splice and R = 1**: fails (no convergence, garbage). The package default K = 4 combined with `method="maxent"` and R = 1 does this. Needs a guard or a different sigma rule.
* **Impartial(3)** is consistent (never violates the cone) and unbiased at the 1-sigma level for N >~ 500; slightly biased at N <~ 100 (z = 1.3-1.6).
* **The report's statement "the splice is unbiased because each mu_n is unbiased"** is true per moment and for every linear functional (KPM, E_BS at fixed E_F; verified), but it says nothing about the joint list (H1: almost always outside the positive cone) and Maxent (R = 1 breaks). Table I is not contradicted (it uses KPM, N = 16384).

## Proposed text (not applied) for Sec. II B
"Each substituted moment is exactly its true value and each sampled moment is an unbiased estimate of its own, so every linear functional of the list, including the KPM density and the band energy at a fixed Fermi level, is unbiased; I verified this on chains, dimerized chains, Kwon silicon and the Anderson model from N = 32 to 4000 (App. X). The list as a whole, however, is not the moment list of any positive measure: a Toeplitz test shows that it violates positivity at order m ~ 20--40 for all N tested, whereas a single random vector or an impartial vector never does. This is harmless for KPM, whose reconstruction is linear, and for Maxent with sampled uncertainties from R >= 4 vectors (converges in 90--100% of runs, RMSE 6--40 times below plain vectors), but with R = 1 the Maxent solver does not converge. The nonlinear step that fixes E_F from the noisy integrated DOS introduces a small bias that exists for plain vectors as well."
